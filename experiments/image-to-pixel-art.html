How this works

About

Converts any image into a real grid of pixels you can edit and export. It is built for the common case of a sprite that has been upscaled, re-saved as JPEG, or resized by a non-integer amount: it finds the original pixel grid and recovers one clean color per source pixel. Ordinary photos can be pixelized too by picking how many pixels wide the result should be.

How to use

  • Import — drop, paste (Ctrl/⌘+V) or pick an image, or try the sample sprite. The detected grid is drawn over the source preview; zoom in to check it lines up.
  • Grid — tweak cell size / offset if detection is off, or drag the Resolution slider (or type Pixels across) to rescale in real time — handy for pixelizing photos. Detected jumps back to the auto-detected grid. Use Center median sampling for sprites and Cell average for photos. Changing the grid re-samples the image (undoable).
  • Edit — Pencil B, Eraser E, Fill G, Replace color R (all pixels of the clicked color), Eyedropper I. Right-click paints transparent with any tool; Alt+click picks a color. Undo Ctrl/⌘+Z, redo Ctrl/⌘+Shift+Z or Ctrl+Y. Ctrl+wheel zooms around the cursor. Pan with the Hand tool H, by holding Space and dragging, with a middle-mouse drag, or with two fingers on touch screens (pinch to zoom).
  • Palette — click a swatch to select it and make it the brush color. Then recolor every pixel of that color, make it transparent, merge it into another swatch, or highlight where it is used.
  • Reduce colors — drag the slider to merge the palette down to N colors (live preview, one undo step).
  • Export — PNG at any integer scale, or SVG with one path per color.
  • Save / open / delete — projects are kept in this browser only (nothing is uploaded). Save (Ctrl/⌘+S) updates the open project; Save as new makes a copy. Undo history is not saved. Clearing site data removes saved projects.

Technical details

Grid detection. For each column boundary the tool sums color differences between neighboring source columns (and the same for rows), giving an "edge energy" profile. Pixel-cell edges repeat with period p, so it evaluates the Fourier coefficient Σ E[x]·e−2πix/p for a fine sweep of fractional periods. The normalized magnitude measures how well edges line up on a grid of that size, and the phase gives the grid offset. Divisors of the true size (p/2, p/3…) also score highly, while multiples cancel out, so the largest strongly-scoring period is chosen and then refined per axis — this handles cell sizes like 7.37px from non-integer resizes.

Sampling. Each cell takes the per-channel median of its central ~60%, which ignores blurred/JPEG-damaged borders. Cells that are mostly transparent become transparent. Near-duplicate colors (compression noise) are then merged in OKLab space using a spatial hash.

Color reduction is weighted k-means in OKLab with farthest-point seeding (deterministic). With Keep original colors each cluster snaps to its real member nearest the centroid, so hand-picked sprite colors are preserved instead of averaged into mud.

SVG export merges horizontal runs of equal color, extends them downward while the run below matches, and writes one <path> per color with shape-rendering="crispEdges", so it stays small and each color is easy to edit.

Saving uses IndexedDB: each project stores its pixels as a raw ArrayBuffer, a thumbnail, the grid/sampling settings and (optionally) the original image file as a Blob. The page asks the browser for persistent storage so saved work isn't evicted when disk space runs low.
